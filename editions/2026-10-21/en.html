EMudhra Intermediate CA Compromise

Background

Background

Intermediate CAs are delegated signing layers that issue certificates on behalf of a root CA; compromising one lets the operator revoke that intermediate without invalidating the root or sibling intermediates. Revocation has long been the weak point of TLS: browsers check CRLs or OCSP, and Mozilla has layered on OneCRL for intermediates and CRLite for leaf certificates, but many TLS libraries and embedded clients perform little or no such checking.

eMudhra's intermediate ECC certificate authorities were found to have effectively guessable private keys, reportedly single-byte values (one of them literally "4"), traced to a flaw in the KGC script used on a specific day to create those ECC issuers. Browser vendors responded by revoking trust in the affected intermediates, while non-browser TLS clients that do not use modern revocation tooling remain exposed.

Because the intermediate CAs were publicly trusted, anyone who could guess the keys could have forged certificates for arbitrary domains, and that risk falls unevenly across the ecosystem. A Mozilla engineer said Firefox users were protected automatically within a couple of hours via OneCRL, with Chrome, Apple and Microsoft operating similar tooling, but "for the rest of the ecosystem, there has been little to no investment in revocation."

In Mozilla bug 2083449, eMudhra said its preliminary assessment found "a flaw in the KGC script that was used on that specific day to create these ECC issuers," and that review of the KGC code and HSM keys so far indicates a set of original ECC keys was created onboard as expected plus an approved deviation to its usual KGC. Community reports describe eight affected CAs, and one commenter said the keys were allegedly found at a public repository URL, while noting uncertainty about whether the artifacts show stolen keys or a weak generation process.

hackernews · galadran · Oct 20, 21:58 · Discussion · Single source

Analysis and references

Impact analysis

The exposure runs through TLS trust rather than through any token's fundamentals: crypto exchanges, custodians, wallet backends and node RPC endpoints that terminate TLS in non-browser clients may not consult OneCRL or CRLite, leaving a window for interception of API and webhook traffic until the affected intermediates are removed from those trust stores. Browser-facing services were largely covered by vendor-side revocation, so the residual risk concentrates in server-to-server and embedded/IoT infrastructure.

Discussion

Commenters reacted with disbelief and derision at the single-byte key material, with one noting they put "compromised" in quotes "because I can't call it that without cringing." A Mozilla engineer's explanation of OneCRL/CRLite remediation and the uneven state of revocation across the ecosystem drew the most substantive attention, and others asked for a qualified account of whether the keys were leaked or merely guessable.

Mastercard opens early access to AI agent payments following pilots with Coinbase, Base and Cloudflare

Background

Background

Mastercard first announced plans for the system in June and has since run end-to-end pilots with Cloudflare, Ant International, AWS, BVNK and Coinbase. x402 is an open protocol that revives the long-dormant HTTP 402 "Payment Required" status code, allowing services to quote a price and a receiving address so software agents can pay directly. Mastercard acquired stablecoin infrastructure firm BVNK in August.

Mastercard has opened early access to a system called Agent Pay for Machines, which lets autonomous software agents discover services, agree to terms and pay for them within human-set spending limits. The company unveiled the milestone at Cloudflare's Connect conference, where Mastercard's Jorn Lambert demonstrated a live transaction.

Mastercard frames the system as a fix for a specific friction: paid online services typically require an account, API key or billing relationship with each provider, which breaks down when an agent selects services on the fly. The launch follows end-to-end pilots with Cloudflare, Ant International, AWS, BVNK and Coinbase.

Agent Pay for Machines builds on the open x402 protocol: when an agent hits a paid service returning a "402 Payment Required" response, it generates a digitally signed payment voucher that the provider verifies before delivering the service, with vouchers batchable for later redemption. In the demo, an agent for marketing agency Hype ran a protein-bar campaign across nine payments to two independent merchants on a single budget, with Coinbase supplying the wallet, Base providing on-chain settlement, and BVNK handling fiat or stablecoin settlement through Mastercard's Global Money Platform; Mastercard is also releasing buyer- and seller-side APIs, a developer toolkit and a testing environment.

Google open-sources TorchTPU, a native PyTorch back end for TPUs

Background

Running PyTorch on Cloud TPU previously required bridging layers, and Google Cloud documentation describes setups in which frameworks such as Ray provision PyTorch workers per TPU device. Competing accelerator vendors have shipped similar efforts, such as AWS's torch-neuronx for Trainium.

Google has open-sourced TorchTPU, a native PyTorch backend that lets PyTorch workloads run directly on its Tensor Processing Units (TPUs). Google detailed the project on its developer blog, describing an "Eager First" design and XLA integration intended to simplify migrating models to TPU infrastructure.

PyTorch is the dominant framework for model development, so first-party support removes a long-standing barrier that forced teams to bridge through XLA or stay on TensorFlow/JAX to use TPUs. Community commenters framed the release as accelerating the shift away from TensorFlow and widening the set of accelerators PyTorch code can target.

The project was first reported by Reuters in December, and Google has now officially confirmed and detailed it; The Stack reports that multiple Google staff were dedicated to building the backend. Google's developer blog highlights XLA integration and peak-efficiency execution on TPU infrastructure as core goals.
