    BTCPay Server: Attack surface points to version 2.4.1 and earlier, no credible hot wallet theft reports on latest release

    On November 2, BTCPay Server said its incident response investigation had identified an attack vector mainly targeting instances running version 2.4.1 — released July 23, 2026 — or earlier. The project said it has received no credible reports of hot wallet drains among users running the latest release, version 2.4.7, and again urged all operators to upgrade promptly. BTCPay Server is self-hosted payment infrastructure run directly by merchants, so the exposure is concentrated among operators who have not updated past 2.4.1. BTCPay has not disclosed how many operators were affected or the value of any stolen funds. BTCPay asked affected users to submit information and logs to its security team, and has not released technical details on how attackers accessed the wallets. Cointelegraph said it reached out to BTCPay Server for comment but received no response before publication.

    BTCPay Server Urges Shutdown After Reports of Hot-Wallet Sweeps

    BTCPay Server, the open-source self-hosted Bitcoin payment processor, advised operators to shut down their instances after reports that hot wallets tied to the software were being swept, indicating an active security incident affecting Bitcoin merchants. The project's guidance also directed operators to update to version 2.4.2, which refreshes LND and regenerates its admin macaroon. Merchants running their own BTCPay instances hold the keys to the funds those servers control, so an active draining incident exposes them to direct loss until they shut down or update. BTCPay is a widely used self-hosted alternative to custodial payment processors, giving the advisory an unusually large operational footprint. The incident appears tied to a Lightning credential flaw in versions before 2.4.2 that let attackers obtain the credentials controlling a store's Lightning funds. The project said operators unsure whether an update applied correctly should re-run it via the user interface or btcpay-update.sh; the exact loss magnitude and root cause have not been resolved in reporting.
