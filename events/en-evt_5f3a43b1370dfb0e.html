Current outcome

Alpine Linux has published a security advisory for the OpenSSH-server password authentication bypass, explaining the technical details of musl crypt() error return allowing long-password bypass of passwordless accounts; the OpenSSH 10.6p2 workaround has been released.

Progress timeline

2 material updates
  1. #0111.05
    Escalation14:44 UTC · publication time

    Alpine Linux Security advisory: OpenSSH-server password authentication bypass

    Alpine Linux published a security advisory detailing the OpenSSH-server password authentication bypass: musl's crypt() returns the error indicator '*' when the key exceeds 256 bytes, which matches the stored hash field of accounts without a password, allowing long-password logins to succeed.

    State after update: Alpine Linux has published a security advisory for the OpenSSH-server password authentication bypass, explaining the technical details of musl crypt() error return allowing long-password bypass of passwordless accounts; the OpenSSH 10.6p2 workaround has been released.

    Source evidence: pantalaimon

  2. #0211.05
    Initial11:40 UTC · publication time

    OpenSSH 10.6p2 Critical workaround for alpine without PAM

    OpenSSH published 10.6p2 release notes with a critical workaround for Alpine systems built without PAM, and the maintainers explained they are moving away from long vulnerability embargoes because AI agents are now rediscovering bugs within hours.

    Source evidence: selckin
