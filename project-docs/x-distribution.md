# X 自动分发

用户于2026-11-09授权跳过试运行，完成质量门和现有凭证校验后直接在 @ohxiyu 运行，不购买或升级套餐。本阶段默认开关仍关闭；只读验证不发送、不生成队列。Premium 未确认，统一限制280加权字符。

## 开关与触发

仓库变量 `X_DELIVERY_ENABLED` 的 `true`/`false` 覆盖 `data/config.github.json` 中 `x_delivery.enabled`；未设置时使用配置默认值，非法值拒绝执行。关闭后保留回执和历史。

成功的 `xiyunews Cloudflare` 部署触发检查；Worker五分钟主时钟及每小时Actions定时作为补充。触发不等于发送授权。必须找到当前原始选稿的精确部署证明，并验证其源头是本仓库main成功的 `daily-summary.yml`。纯代码部署、旧日期、选稿哈希不符、证据缺失均不发送。还会读取实际首页、单期页、API，逐条比较中文标题、摘要、背景、URL、分数、修订。代码部署不为历史日报补发X。

Actions手动输入 `verify_only: true`：只调用现有OAuth凭证的 `GET /2/users/me`，验证用户名、可读取时记录粉丝基线；同时用现有日报bot读取频道公开用户名。不会发送测试推文、修改队列或披露私人ID。GET成功只能证明账号读取权限；实际自然发送返回推文ID后才能证明写入权限。

## 质量门

- 分数≥8、中文标题及摘要、一手或原创来源，非简版；比特币和安全类优先，不改变原分数。
- 来源校验同时要求已启用配置身份及实际HTTPS域名/Telegram频道/GitHub发行仓库。Google News、来源回退、未知来源、律动和Foresight发现线索不进X。
- 模型只从已发布摘要和背景选择两句完整中文句子，第一句必须来自摘要；不允许自由改写、截断、换单位或删除否定/限定词。只有完整句子匹配且满足风格规则的文案才入队。
- 两段、无链接/话题/emoji/列表/标题党/价格预测/买卖建议。280加权字符内，中文通常每字计2。无合格文案就跳过，不使用模板凑数。
- 相同素材的拒绝结果按质量协议指纹缓存，后续轮询不重复付费生成。发送前再验证实际页面和已保存文案。

## 时间与回执

每天最多2条，07:26–23:30上海时间；第一条以实际验证的出刊时间为准，第二条在第一条实际成功时间后随机180–360分钟。晚于13:26首次出刊，当天不推。每条有效期6小时，跨日作废；过去7天已发或已尝试故事不重复。

队列位于独立 `x-queue` 分支的 `data/x-queue.json`。请求前必须把 `pending` 回执普通push成功，失败则不请求；请求后保存确认结果，禁止force push。持久SQLite同时保存回执，普通检查点负责同步审计分支。

| 结果 | 行为 |
| --- | --- |
| 成功并返回数字推文ID | `sent`，保存实际确认时间 |
| 连接未建立/429 | 截止前同文案可再次尝试 |
| 401/403/其他4xx | `failed`，停止该期后续发送，运维告警 |
| 超时/5xx/成功但无ID/中断pending | `unknown`，永不自动重发，运维告警 |

failed/unknown 状态与保存的正文可在运行报告、队列回执中核对。工作流最终读取运行后的队列标记待处理情况，不使用过时的运行前计数。

人工处理必须先核对账号：确实已发可标记 `sent` 并填写真实数字ID；确认不发可标记 `void`。确认未发且要重试才可人工恢复 `planned`，并先修复凭证/权限。保留原正文、任务身份和尝试记录，禁止通过清空队列重发历史。
