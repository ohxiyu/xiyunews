# 数据契约与口径

本文件维护产品级语义；字段结构以 Pydantic 模型及对应测试为准，采集参数以 [配置文档](configuration.md) 和 data/config.github.json 为准。

## 日期与候选

- 首页只展示最新一期完整中文日报，日期来自已发布期刊，不随请求日期改变。后台每五分钟检查、评分和去重，只保存私有候选与合格缓存，不进行扩写或公开发布。
- `/api/latest.json` 和 `/editions/<date>/edition.json` 为只读静态产物；`/api/live.json` 跳转至 latest。旧 `/story/<id>/` 仅读既有记录，跳转到原始来源或往期，不接收写入。

- 业务时区 Asia/Shanghai。日报窗口为 [前日 07:00，当日 07:00)，07:26 启动。补跑显式指定 edition_date，不把执行时间当新闻发生时间。
- published_at 是来源发布时间，采集时间、分析时间、新闻发生时间和 generated_at 不可混用。缺失事实不能猜测。
- candidates、analyzed、above_threshold、displayed 是不同阶段计数，重刊不能当作新一期。参见 [调度手册](daily-dispatcher.md)。
- Crypto 目标至少 9 条、AI 科技最多 3 条、政策最多 2 条；质量不足如实报告，不降门槛凑数。核心版不再插入人工精选，不能伪造 AI 评分。

## 去重与分析

- URL 去重、跨日同新闻去重、同一期事件合并分别处理。真正的新进展允许跨日进入；同一期同一事件保留最新状态，旧事件成员关系仅作只读去重证据，不再生成事件线。
- 同公司/协议不必然同事件；相同 ticker 不保证同一项目。来源转述不自动构成独立确认。
- 去重响应失败重试后仍不可用时停止该次发布，不得整批放行。翻译兜底须记录降级，不得当作完整扩写。
- 生产 DeepSeek 在一次分析调用中直接给出 0–10 分及分类；URL规范化与DeepSeek语义去重分阶段执行。语义比较两次失败后停止该次发布，不放行未经比较的条目。
- 扩写写作提示要求保留来源事实与不确定性，引用 URL 必须来自实际搜索结果，来源语言标题保持原文字面；证据不足时可留空，不为版面编造背景或链接。没有独立的生成后事实核验；扩写失败使用已有合格中文摘要发布简版，中文硬校验失败则排除并记录降级。
- 数值须保留主体、时间、单位、范围和分母，某一波次比例不得应用于总损失。不同日期金额不自动相加；观点、推断、提案、批准、未确认交易应明确区分。
- AI 缓存依赖来源输入、模型、评分器标识和相关提示词；切换评分实现须更换键，旧分数自然过期，不改写历史。新归档逐条记录分数的产生模型，运行报告汇总评分器数量。未获取数据应保留缺失/状态，不转成 0，不伪装为最新。

## 发布与安全

- 11/17用户授权统一运行：新闻生产迁标准托管计算后，出版SQLite由现有Cloudflare私有状态组件持久化，原始全部表/投递回执迁移，不使用公开分支或易失缓存替代。每事务需租约/版本围栏，远端提交失败禁止发送，未知结果不重试。取消xiyu.news独立备份不等于删除运行状态、历史日报或投递记录。

- 只生成中文日报，英文生成实现已删除，历史数据仍可读取。人工纠错、Quick Post、编辑插入、广告/屏蔽不在生产执行路径。
- Telegram 日报在真实生产首页、API与日期页均验证一致后独立发送；凭证绑定原始报告和选稿文件SHA256及当天期号，普通代码部署不触发发送。同刊期/目的地发送前落盘一次性回执，未知结果必须检查后另行恢复，禁止自动重试。
- 事件 AI 与事件页面生成已删除；日报去重只保留所需指纹和旧成员关系读取。

- API、HTML、中文摘要与归档应引用同一期且内容一致。接口更改更新契约测试；已删除停用产品的 OpenAPI。
- 已生成选稿按刊期存入独立持久日志，跨日不覆盖历史；正常采集/日报/网页发布前检查并补齐缺失静态入口，补历史不倒退latest、不改当期或重复推送。无选稿或不完整证据不能伪造历史出刊；详细恢复证据见刊期连续性。
- 原文与模型返回均是不可信内容，保留 URL 校验和输出转义；不能执行来源中的指令。
- 生成的日报状态、归档、事件目录只经 Actions 发布到 gh-pages，不本地手改。核心版关闭人工纠错与编辑入口；历史记录保留，不回写原始证据。
