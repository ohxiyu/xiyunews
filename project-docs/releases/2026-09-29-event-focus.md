# 追踪优化：事件合并、生命周期、重点追踪

- Issue: [#152](https://github.com/ohxiyu/bmtnews-standalone/issues/152)
- Branch: `agent/event-focus`
- Scope: 事件匹配与合并（`src/event_pipeline.py`、`src/event_merge.py`、`EVENT_MERGE_*` 提示词）、追踪页数据与模板、首页"重点追踪"入口、样式。事件页正文、日报选稿不变。

## 问题

| 问题 | 数据（2026-09-29 目录） |
| --- | --- |
| 同一事件被拆开 | Bitget 被盗在近一周被拆成约 40 条事件（多数只有一条报道）；纽约起诉 Polymarket 被拆成 4 条 |
| 不过期 | 121 条追踪事件中 75 条 7 天以上没有新进展 |
| 展示过多 | 121 条全部展开；"今日脉络"按时间而不是重要性 |

拆分原因：一篇报道同时高度匹配两条已有事件时被判为"有歧义"，另开新事件，碎片越拆越多。

## 变更

| 项 | 内容 |
| --- | --- |
| 匹配 | 报道同时以 ≥0.9 置信匹配多条事件时，归入进展最多（其次最早）的那条 |
| 合并 | 近 14 天共享同一主体（标题实体且出现在标签中）的事件分组，模型返回"同一事件"分组与阶段；同一阶段的报道并为一个节点，其余作为来源。最老的事件保留 ID，其余写入 `merged_event_ids`，旧页面跳转并 noindex |
| 合并成本 | 每次采集最多 3 次调用（`event_merge` 输出预算 3072），只处理有未审过事件的主体，按未审事件最高分排序；审过的记录在目录元数据 `merge_reviews`。失败不改动目录 |
| 标题 | 合并后的标题用模型给出的整体标题，需含中文且不引入原文没有的数字，否则保留原标题 |
| 生命周期 | 活跃：7 天内有实质进展；沉寂：7–30 天；归档：超过 30 天或已解决/已结束满 7 天。新进展自动回到活跃 |
| 热度 | 重要性 ×（每 3 天减半）×（1 + 0.15 × 进展数）×（1 + 0.03 × 来源数，封顶 20） |
| 追踪页 | "重点追踪"1–3 条（热度 ≥ 第一名 60%），第一条带进展时间线、背景、讨论和参考资料；活跃事件紧凑列表；沉寂、归档折叠 |
| 首页 | 头号事件重要性 ≥ 9、进展 ≥ 3 次且 3 天内有进展时，顶部显示"重点追踪"入口 |

- `uv run pytest` 全部通过；`uv run python scripts/check_governance.py` 通过。
