# AI 内容覆盖

- Issue: [#138](https://github.com/ohxiyu/bmtnews-standalone/issues/138)
- Branch: `agent/ai-coverage`
- Scope: 选稿分组、首屏「今日脉络」、评分提示中的 AI 锚点。榜单仍是一张按重要性排序的列表，不新增栏目；X 分发与信源不变。

## 变更

| 项 | 基线 | 现在 |
| --- | --- | --- |
| AI 名额 | AI 与 Hacker News 共用 `technology` 组，上限 3；近两周 AI 占 15%（26/172） | `technology` 只含 ai-labs / ai-devtools / ai-media，`min_items: 3`、`limit: 5`；`tech-community` 单独一组上限 1。保底名额在开放排序前先填，只选已过 7 分阈值与去重的候选；不够 3 条就少于 3 条，不降低门槛 |
| 首屏 | 提示词写明不强制覆盖 Crypto/AI | 每条故事标注 [Crypto]/[AI]/[Policy]；要求 2–3 条要点并覆盖最高排名的加密故事与 AI 故事。模型给出了结构化要点但漏掉某领域时，用该故事已发布的标题补位（标签「加密」/「AI」）；只剩一句标题的降级路径保持不变 |
| 评分 | 校准锚点只有加密场景 | 增加 AI 锚点：小更新≈6.0；重要开源权重/开发工具/有实际义务的政策≈7.0–7.5；前沿模型/重大安全事故/改变 AI 研发部署的裁决≈8.0–8.5；行业重塑事件≈9.0+ |

## 影响

- 评分提示变化会让分析缓存全部失效一次，上线后的首期会重新分析全部候选（一次性 token 成本）。
- 当前 AI 信源较少（近两周日均约 1.9 条 AI 入选），在信源调整之前，保底 3 条多数天会达不到。这是预期行为，不会用低分内容凑数。
- 新分组 `tech_community` 在后台信源控制台归入「AI 科技」轨道；公共 JS 改动已同步 `asset_version`。

## 验证

- `uv run pytest` 全部通过（离线）。新增：保底名额挤出过多加密条目、候选不足时不凑数、`min_items > limit` 被拒绝、生产配置下 AI 为 3–5 条；首屏补位覆盖、已覆盖时不改、只有加密时不虚构 AI、仅标题降级不变。
- `uv run python scripts/check_governance.py` 通过。

## 尚未验证

- 真实模型对新首屏规则的遵守率，以及 AI 锚点对分数分布的影响，需观察上线后 3–5 期。
