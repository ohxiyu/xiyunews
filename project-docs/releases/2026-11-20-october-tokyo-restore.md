# 十月版与东京执行器恢复

基线为十月中旬已生产的 [c6814f9](https://github.com/ohxiyu/xiyunews/commit/c6814f9c9e3e47012a3d63fdd49bfc8b599766df)。草稿首个提交 cdd6aa2 的 Git tree 完全相同。后续提交只更新依赖和这次的交接证据。前后端应用源码仍取自十月基线。

依赖调整使用现行 Worker 安全锁，并逐项更新 Python 审计所报依赖。漏洞修复后的 Soup Sieve 需要 Python 3.11.5，恢复草稿采用与现行应用一致的下限。现有和更新后的 Python 测试通过，修复后 135 项 Worker 测试、TypeScript 检查及两类安全审计通过。

部署前以原可信 SSH 配置接入东京，并用仓库管理身份重新注册专用 runner。切换前确定当前活跃私有 SQLite 和投递记录的接续方式。旧程序早于现行账本，实际切换须完成只读核对和发送去重验证，再交接唯一写入者。旧版供应商配置需要验证原账号凭据和既有预算。现行已发布档案以 gh-pages 为准。已取消的备份、独立实时服务及同机其他应用沿用现有操作边界。

当前只保存草稿。东京 SSH 别名无法在本云环境解析，且未连接 SSH 代理；GitHub Runner 管理也无法从当前凭据访问。现行 main 和生产服务维持当前状态。
